# AETHEREAL 3D — Project Rules

## Stack
- Godot 4.7, GDScript, Forward+ renderer, Jolt physics. NOT Godot 3.
- 3D third-person action game with a PS1 look.
- Renders at 960x540 and scales up with hard pixels (2x at 1080p). The author wants "PS1 but clean":
  chunky texels and the dither, but no shimmer, little warping, crisp flat textures.
- Art direction (2026-10-25, the author): "our own style": PS1-flavoured but not bound to PS1
  hardware ("we might even go PS2"). The environment stays simpler and chunky; characters are more
  detailed, "cool but stylized", like Lorn's Lure's characters, never FF7-field low. Aeneas is
  inspired by Jim Hawkins (Treasure Planet); Kael's theme is red and/or white.
- Pipes follow walls and corners with purpose (`_duct` polylines in the dressing scripts: a box per
  run, an elbow cube per bend, straps every 3 m). Square ducts or round pipes, both fine (ruled 2026-10-24).
- The older 2D metroidvania prototype is a separate project in
  `OneDrive - Ucio IT Services/Documents/Aethereal/Aetheral (game)/aethereal`. Don't edit it from here.

## The PS1 look — keep it consistent
- Every 3D mesh uses `shaders/ps1_surface.gdshader`, directly or through a material in `materials/`.
  Never StandardMaterial3D. One exception: a GPUParticles3D draw-pass material (steam_vent.gd), which
  the PS1 shader cannot drive.
- Vertex wobble is one global knob: Project Settings → Shader Globals → `ps1_snap_resolution`.
- 15-bit color + dither covers every scene through the `PS1Screen` autoload (`scenes/ps1_screen.tscn`).
- Textures: small (64–128 px), nearest filtering WITH mipmaps (`filter_nearest_mipmap`, imports
  have `mipmaps/generate=true`): crisp up close, smooth far away. Without mipmaps distant walls
  shimmer into noise, which the author dislikes.
- Keep the textures low-contrast and low-frequency: soft seams, little grain, big panels. Fine
  lines read as noise at distance.
- Affine texture warping is OFF (`affine_amount` defaults to 0 in the shader; the near/far easing
  stays for any material that turns it on). The author saw walls swim even at 0.35 (2026-10-24):
  the references (myhouse.wad, Lorn's Lure) have none. The wobble grid is 640x360.
- No real-time shadows. Characters get a blob shadow (a Decal that only hits render layer 1).
- Low poly. Fog hides the draw distance. Big surfaces need subdividing, or the texture warping gets ugly.
- Levels are built from `scripts/block.gd` (Block): a box with matching collision, split into ~2 m
  squares, with vertex-colour grime at the foot of side faces. Mesh UVs are 0..1 per face (props)
  or, with `trim` on, metres along x 0..1 across (trim-sheet strips). World-mapped materials ignore
  mesh UVs. Buildings use `materials/facade*.tres`: windows on walls, plain tops (`use_top_texture`).
- Buildings are Blocks with `style = BUILDING` (`scripts/building_faces.gd`): a 3.2 m base course with
  doors and shopfronts, 3 m bays and storeys, blank corner piers (>= 1 m), slab lines, a 0.6 m parapet,
  a plain roof tile. Tiles come from `textures/building_atlas.png` (20 x 2 tiles of 64 px: 0 blank,
  1-7 and 13-15 windows, 8 base blank, 9 door, 10 shop, 11 roof, 12 parapet, 16-19 megastructure bays
  of tiny slit windows), painted by paint_building_atlas.gd. A Block with metadata `faces_dense_above`
  (world metres) uses the megastructure bays for storeys above that height (Blame!-scale upper floors).
  Rules the author asked for: no windows on edges, roofs or undersides; a face under 5 m wide or
  4 m tall stays blank, so an extrusion never continues the main wall's texture; doors that don't open.
  A BUILDING block builds its mesh in `_ready` (its doors are picked from its position) and rebuilds
  when moved in the editor. Set `ground_floor = false` on any block that does not stand on a street.
- The Empty Town's sky is a prerendered far city (`textures/backdrop_city.png`, six cube faces, shown by
  `shaders/sky_backdrop.gdshader`; regenerate with scratch r8_sky/render_backdrop.gd, windowed). Its haze
  is the fog colour, so the Environment keeps `fog_sky_affect = 0`; change both together.
- A script that extends Block must be `@tool` too (tool mode is not inherited, so the editor would
  show nothing), and must guard its runtime behaviour with `Engine.is_editor_hint()`.
- Scripts that change a Block's look while the game runs call `set_runtime_material(copy)`, never
  `material = copy`: a scene saved afterwards would bake the copy in and lose the shared file.
- The painted texture set is generated by a scratch script (paint_textures.gd); to change a texture,
  regenerate, don't hand-edit pixels. Decals use Godot's Decal node with `cull_mask = 1`.
- A third-person camera can't see straight down past a railing. If the player must look down at
  something, give them a balcony with a low lip.

## Combat
- `scripts/player_combat.gd` (a child of the Player): lock-on, stamina, light/heavy, dodge,
  block, parry, riposte, and the eruption mode. Enemies call `take_hit()` on it.
- Lock-on is only a helper (the author, 2026-10-25): without it a swing or quick draw turns him
  toward the nearest enemy roughly ahead and steps in a little (`scripts/swing_assist.gd`); the
  camera is never moved by it.
- A Fight with a `choreography_file` (`data/fights/*.txt`, parsed by `choreography_file.gd`, run
  by `choreography.gd` in place of the Fighter's AI) plays authored beats: the captain's set piece.
  Hits don't break a choreographed beat; a parry does. Phase 2 starts when the boss is empowered.
- Guards fight through `scripts/enemy_fighter.gd` (child "Fighter"); `Guard.fights` makes a
  sighting start a fight instead of a stealth restart; `dormant` holds him until `[fight X]`.
- Every guard duplicates its GuardData in `_ready`, so `empower()` only changes that one.
- New input actions are registered in code (`_ensure_actions`), not in project.godot, so the
  editor being open can't overwrite them. Move them into the Input Map when convenient.
- Fighters path over a NavigationRegion3D when the level has one (`enemy_fighter.gd` asks
  NavigationServer3D for a path; with no mesh they walk straight). The Empty Town's mesh covers the
  courtyard and hall: `data/nav/empty_town_navmesh.tres`, its settings in the resource (agent radius
  0.25 so a 0.35 capsule can't stand off it, groups mode, level root in group `navmesh_source`).
  Rebake in the editor (Navigation node, Bake NavigationMesh) or with scratch bake_nav.gd.
- Ramps get side rails: near a bare ramp's foot the navmesh thinks the side is climbable and the
  capsule can't step onto it, so agents pin themselves there.
- Guards don't collide with each other (a crowd jams ramps); `_separate()` pushes them apart softly.
  `dormant` guards ignore hits, staggers, lock-on and takedowns. A Fight can switch on an Area3D when
  won (`unlock_on_win`), used to hold the capture until Aeneas walks to the hall door.

## Sound and life signs
- `scripts/sfx.gd` is the "Sfx" autoload (a pool of 3D players, `play(name, at, volume_db)`,
  `loop_at(name, at, volume_db, parent)`); gameplay scripts reach it only through the static
  `SfxBus` (`scripts/sfx_bus.gd`), never by the autoload's name (see the autoload rule above).
  With no Sfx running (headless tests) every call is a no-op.
- Sounds are WAVs in `audio/`, synthesized by the scratch script make_sfx.gd; placeholders until the
  author replaces them. Footsteps pick their set from the floor's material path (metal_plates /
  grating → plates, pavement / dev_grid → pavement, else concrete), spaced by the Player's strides.
- Ambient loops live in the level as AudioStreamPlayer3D nodes so the author can tune them in the
  Inspector. Mix levels were set blind (headless); the author judges them by ear.
- Life signs are small scripts under a level's `Life` node: `flicker_light.gd` (personalities),
  `tv_window.gd` (a Block whose emission cycles; duplicates its material), `steam_vent.gd`
  (GPUParticles3D built in code), `drip.gd`. They must survive a headless run (no editor-only API).

## Story and dialogue
- Scenes are plain text in `data/dialogue/<level>.txt`, played by the `Story` autoload through
  StoryTrigger areas and Camera3D shots under each level's `Shots` node.
- The words are the author's. Draft lines only from beats we agreed on, mark the file DRAFT, and
  prefer narration over inventing what characters say.
- Gameplay scripts must not name autoloads (e.g. `Story`) directly: test scripts that load them
  before autoloads register fail to compile. Pass state through the Player instead (e.g. `in_cutscene`).
- Exporting: add `*.txt` to the export preset's "non-resource files" filter, or the dialogue won't ship.
- Look-at prompts: `scripts/interactable.gd` (an Area3D under the level's `Inspect` node) shows
  "E / Up: <label>" through `hud.show_hint` and narrates the lines from `data/inspect/<level>.txt`
  (`NodeName|line|line`). Those lines are the author's too: draft, mark DRAFT, let them rewrite.
- A look pauses the world (it plays as a scene), so prompts are not offered during a fight. Story
  hands control back two physics ticks after a scene ends, so the closing press is not also a swing.
- Checkpoints and StoryTriggers wait for `player.land_safely()`: a zone he passes through on the way
  down a fatal drop (over `fall_death_height`, 6 m) doesn't count, or a fall restart would put him past
  the section he skipped.
- Checkpoints only move forward: the StealthDirector ranks them by their order under the level's
  `Checkpoints` node (and, in the big world, by zone order first), so keep that list in route order.
  A lost fight waits for the director's `restarted` signal before it starts again (pause-safe).

## Rough-cut levels (Act 0 onward)
- Each story location gets a rough walkable level first: signature space, landmark, its own fog
  and light, beats told through dialogue scenes. Detail comes later, after the author walks it.
- Levels chain with `[level ...]` at the end of a dialogue scene; the title screen's Chapters page lists them all.
- The town, Black Sand and the station are one big world (`scenes/world/world.tscn`, the author asked
  2026-10-25): each level is instanced as a WorldZone and stays runnable alone (F6). The world removes
  each level's own Player/StealthDirector and uses one of each; links (`scenes/world/*.tscn`) are the
  walkways and list the level pieces they replace, so the level scenes are never edited for the world.
  Only the zone Aeneas is in is shown and processed (both on a link). A `[level]` line for a world level
  loads the world at that zone's Start (or, inside the world, lets him walk on). Story lookups search the
  scene's own level first. Zone boxes must not overlap; geometry of hidden zones may overlap other zones.
- Walkable means no steps: CharacterBody3D won't climb a ledge, even 30 cm. Use ramps, keep floors
  flush (a 2 cm lip is fine).
- Terrain meshes: triangles must face up (normal.y > 0) or collision and sight lines fall through.
- **Godot's front faces are CLOCKWISE seen from outside.** A mesh built with the right-hand
  (counter-clockwise) rule is inside out: you see through buildings and floors vanish. The
  Block mesh and the dune mesh emit clockwise. Test any new mesh by putting a camera inside a
  closed box: a correct mesh shows only the background (scratchpad test_winding.gd).

## Hand-editing .tscn files
- A node that sets an exported Node property (e.g. Isabella's `leader`) needs
  `node_paths=PackedStringArray("leader")` in its `[node ...]` header. Without it the link loads as null.
- Godot open on the project will overwrite scene and settings changes. Ask before editing those files.

## Layers
- Physics: 1 = world, 2 = player, 3 = enemies. Sight lines, Isabella's checks and the camera only
  look at layer 1, so bodies never block a view.
- Guards are one scene (`scenes/guard.tscn`); kinds come from GuardData files in `data/enemies/`.
- Render: 1 = world, 2 = characters (the blob shadow skips layer 2).

## Godot 4 syntax — do not regress to Godot 3
- CharacterBody3D, not KinematicBody; move_and_slide() takes no arguments; set `velocity` first
- @export and @onready annotations, not the export/onready keywords
- Signals: node.signal_name.connect(callable), not node.connect("signal", ...)
- Tweens: create_tween(), not the Tween node

## Architecture rules
- Data over code. New enemies, abilities, and sacrifices are .tres resources in data/, never new scripts.
- ONE base enemy scene. Variants come from data. Do not create per-enemy scenes.
- Systems talk through signals, not direct node references across trees.
- No file over ~300 lines. Split it.
- No feature is "done" until the game runs and I have played it.
- Code-built meshes (Blocks, prop scripts) build ONCE, when the node is in a scene: setters call
  `_rebuild()` = `MeshBuild.request(self)`, the work goes in `_rebuild_now()` (`scripts/mesh_build.gd`).
  Never build in `_init` or on every setter, and never pass a PrimitiveMesh to
  `SurfaceTool.append_from` at runtime (a GPU round trip per piece): use PropMesh. Rebuilding on
  every setter made New Game freeze for 30 s on the author's Iris Xe laptop.
- Scene changes go through Story (`go_to_level`, `[level]`), which loads on a thread behind the fade
  (`scripts/scene_loader.gd`); don't call `change_scene_to_file` on a level from gameplay code.
